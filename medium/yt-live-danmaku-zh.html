我做了一個把 YouTube 直播聊天室變成 Bilibili 彈幕的 Chrome 擴充功能——七個坑的完整記錄

「把留言變成飄過去的字」聽起來是週末小專案，實際做下去每一步都有坑。這是 yt-live-danmaku 的完整踩坑與修正記錄，全部程式碼約 300 行、只要 storage 權限、MIT 開源。

這個擴充功能做什麼

看 YouTube 直播時，聊天室擠在旁邊的小框裡，眼睛得在影片和聊天室之間來回跳。Bilibili 的解法是「彈幕」——留言直接從畫面右邊飄到左邊，疊在影片上。這個擴充功能把同樣的體驗帶到 YouTube 直播：

  • 即時彈幕——聊天室留言即時轉為彈幕，從右往左飄過播放器，全螢幕也支援
  • 彈道系統——自動分軌、防重疊，過載時自動丟棄避免蓋滿畫面
  • 隱藏原聊天室——開彈幕就自動收起聊天室面板，畫面不出現重複內容
  • 暫停同步——影片暫停，彈幕跟著停；繼續播放，彈幕接著飄
  • Super Chat／會員——SC 金色顯示（含金額）、會員訊息綠色顯示
  • 即時設定——字體大小、速度、不透明度、顯示範圍，調整立刻生效免重整
  • 極簡權限——只需要 storage 權限，不收集任何使用者資料

坑 1：聊天室根本讀不到

問題：YouTube 的直播聊天室不在影片頁面裡，而是一個獨立的 /live_chat iframe。播放器頁面的 content script 因為瀏覽器的 frame 隔離，完全碰不到聊天室的 DOM。

修正：manifest 設 all_frames: true 讓同一支 content script 同時注入播放器頁與聊天室 iframe，依 location.pathname 分成兩種角色：聊天室端用 MutationObserver 監聽新留言，再用 window.top.postMessage() 跨 frame 傳給播放器端繪製。

坑 2：一進頁面彈幕瞬間灌爆

問題：聊天室載入時會一次灌入數十則歷史留言，這些也會觸發 MutationObserver，結果一開頁面整個螢幕被舊留言塞滿。

修正：observer 掛上後先等 1.2 秒才開始送留言，跳過初始灌入的舊訊息；另外用留言的 DOM id 做去重（Set 快取、超過 3000 筆自動淘汰），YouTube 重繪節點也不會出現重複彈幕。

坑 3：彈幕互相疊在一起看不清楚

問題：留言一多，彈幕隨機亂放會互相重疊，長留言跟短留言黏成一團完全無法閱讀。

修正：做了 Bilibili 式的彈道（lane）系統：畫面依字體大小切成數條軌道，每條軌道記錄「上一則彈幕的尾巴完全進場的時間點」，新彈幕只派給已淨空的軌道；全部軌道都擠不下且要等超過 3 秒時，直接丟棄該則留言——寧可少顯示也不要糊成一片。

坑 4：全螢幕就看不到彈幕、換影片彈幕層消失

問題：彈幕層如果掛在頁面 body 上，一進全螢幕就被蓋掉；而且 YouTube 是 SPA，站內換頁不會重新載入，彈幕層會默默失效。

修正：overlay 直接掛進播放器容器 #movie_player 內部，全螢幕時自然跟著放大；同時監聽 yt-navigate-finish 事件加上定期檢查，換頁後自動重掛。

坑 5：影片暫停了，彈幕還在飄

問題：想讓彈幕跟影片同步暫停，但 video 元素的 play/pause 事件不會冒泡，在 document 上普通監聽根本收不到。

修正：改用捕獲階段監聽（addEventListener(..., true)），media 事件雖不冒泡但捕獲照樣攔得到，再用 Web Animations API 的 pause()/play() 批次凍結、恢復所有進行中的彈幕動畫。

坑 6：彈幕跟聊天室同時在畫面上，內容整個重複

問題：彈幕的資料來源就是聊天室 iframe，所以聊天室必須開著；但開著就會跟彈幕顯示一模一樣的內容，畫面重複又佔空間。直覺的兩個解法都不行：按 YouTube 原生「隱藏即時通訊」會直接卸載 iframe，彈幕斷糧；用 display: none 藏起來，iframe 內部可能停止更新，一樣收不到留言。

修正：用 CSS 把聊天室面板 position: fixed; left: -10000px 移出畫面外——版面上它消失了（空間釋出給相關影片），但 iframe 仍完整存活、持續收留言。預設開啟，popup 一鍵切回。這是我們跟「單純疊個彈幕層」的擴充功能最大的體驗差異之一。

坑 7：留言洪水造成播放卡頓

問題：大型直播每秒數十則留言，如果每則都建 DOM、用 JS 逐幀改 left 定位，主執行緒直接被拖垮，影片跟著掉幀。

修正：三層防護：(1) 動畫全部用 Web Animations API 跑 transform: translateX，由合成器（compositor）處理、不佔主執行緒；(2) 同時在場彈幕上限 80 則，超過直接丟棄；(3) 彈幕飄完立即從 DOM 移除，不留殘骸。emoji 則取 img 的 alt 文字還原，不塞圖片節點。

跟同類擴充功能有什麼不同

Chrome Web Store 上已有幾款成熟的同類擴充功能（DanMage、Flow Chat for YouTube Live、YouTube LiveChat Flusher、Danmaku Overlay for Youtube），各有強項——例如 DanMage 支援 Twitch、Kick 等多平台，LiveChat Flusher 有留言翻譯、PiP 等進階功能。我們不是要全面取代它們，而是走「輕量、單一用途、權限最小、開源透明」的路線：

  • 內容重複問題：開彈幕自動把原聊天室收掉（移出畫面而非卸載，留言照收），畫面上同一句話不會出現兩次——這是大多數「純疊彈幕層」的擴充功能沒有處理的。
  • 彈幕可讀性：彈道防重疊 + 過載丟棄，尖峰時段寧可少顯示也不讓畫面糊成一片。
  • 播放效能：動畫全走合成器（transform + WAAPI），留言洪水不拖累影片本身的播放流暢度。
  • 權限與透明度：只要 storage 一個權限，全部程式碼約 300 行公開在 GitHub 上，你可以在十分鐘內讀完並確認它沒有做任何多餘的事。

同類擴充功能功能越堆越多（翻譯、多平台、頭像、NG 名單⋯⋯），對應的是更多權限、更大的程式碼、更難審計。我們選擇相反的方向：只做好「聊天室 → 彈幕」這一件事。

安裝方式

  1. 到 Releases 下載最新的 zip 並解壓縮
  2. 開啟 Chrome，前往 chrome://extensions
  3. 開啟右上角「開發人員模式」
  4. 點「載入未封裝項目」，選擇解壓縮後的資料夾
  5. 打開任一有聊天室的 YouTube 直播，彈幕就會開始飄 🎉
